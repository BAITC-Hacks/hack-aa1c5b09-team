# Технический отчёт по проекту «Ясно»

**Состояние проекта:** 23 сентября 2026 года; учтены изменения до коммита `3480407`.

## Назначение

«Ясно» — веб-приложение, в котором заказчик описывает потребность, оценивает готовность задачи, публикует заявку, получает предложения и выбирает исполнителя. Исполнитель ищет заявки в каталоге, отправляет предложение и общается с заказчиком в чате. Есть личный профиль с редактированием и публичный профиль исполнителя.

## Как устроено приложение

1. Браузер показывает страницы из `frontend/src/pages/`. Маршруты и проверка входа находятся в [frontend/src/main.tsx](frontend/src/main.tsx).
2. Страницы обращаются к общему контракту API из [frontend/src/api/types.ts](frontend/src/api/types.ts).
3. [frontend/src/api/index.ts](frontend/src/api/index.ts) выбирает один из двух режимов: `mock` для демонстрации без сервера или `http` для работы с backend.
4. В режиме `http` Vite перенаправляет `/api` на Spring Boot. Серверные контроллеры вызывают сервисы, сервисы работают с сущностями и PostgreSQL. Настройка прокси находится в [frontend/vite.config.ts](frontend/vite.config.ts).
5. Изменения структуры базы применяются Flyway из `backend/src/main/resources/db/migration/`.

Основные серверные модули: `identity` — пользователи и профили, `needs` — заявки и рейтинг готовности, `proposals` — предложения и выбор, `chat` — сообщения. В интерфейсе им соответствуют страницы входа, создания заявки, каталога, предложений, чата и профиля.

## Что реализовано

- Регистрация, вход и выход; в серверном режиме пароли хешируются BCrypt, сессия хранится на сервере.
- Создание черновика, уточнение задачи, дополнение карточки и публикация заявки.
- Рейтинг готовности задачи: семь критериев, до 100 баллов, явное подтверждение сведений владельцем и пересчёт после изменений. Готовые задачи поднимаются в каталоге, приоритетные выделяются.
- Каталог чужих открытых заявок с поиском, фильтрами и сортировкой по готовности.
- Отправка предложения с описанием решения, стоимостью и сроками; выбор одного исполнителя.
- Отдельный чат для каждого предложения. После выбора остальные чаты доступны только для чтения.
- Личный профиль: имя, специализация, город и описание. Публичный профиль открывается из предложения и не выдаёт email.
- Деморежим без backend: данные хранятся в `localStorage` браузера. Неотправленный ввод сохраняется в `sessionStorage` текущей вкладки.

**Уточнение задачи сейчас работает по семи заранее заданным вопросам в браузере.** В текущем коде нет обращения к внешней языковой модели и нет подключённого ИИ-провайдера. Подготовленные демопредложения и автоответы также работают по сценарию. Рейтинг готовности считается по заполненным и подтверждённым данным, а не по догадкам ИИ. Его контракт описан в [backend/docs/api/READINESS.md](backend/docs/api/READINESS.md). В серверном режиме итоговая карточка, подтверждения, заявки, предложения, профили и сообщения сохраняются в PostgreSQL.

## Данные и безопасность

Сервер использует cookie `JSESSIONID` с `HttpOnly` и `SameSite=Lax`, а для запросов записи требует CSRF-токен. Права доступа проверяются на backend: заявку дополняет её владелец, предложения видят их участники, сообщения доступны только заказчику и соответствующему исполнителю. Публичный API профиля возвращает имя и заполненные публичные поля без email. Схема базы и ограничения целостности описаны в миграциях `V1`–`V4`.

Деморежим предназначен для показа интерфейса: его локальная имитация входа не обеспечивает защиту данных. Для реальных пользователей нужен режим `http` с запущенным backend.

## Запуск

Для полного локального запуска нужны Docker Desktop, Java 21+ и Node.js 22.12+:

```sh
./scripts/start-dev.sh
```

Скрипт запускает PostgreSQL на порту `5433`, backend на `8080` и frontend на `5173`, затем открывает интерфейс в браузере. Адрес: <http://127.0.0.1:5173>. Подробнее — в [README.md](README.md).

Для одного frontend без сервера:

```sh
cd frontend
npm ci
npm run dev
```

По умолчанию включён режим `mock`; на странице входа можно нажать «Открыть демо».

## Проверки и границы текущей версии

- `cd frontend && npm run build` проверяет TypeScript и собирает интерфейс.
- `cd frontend && npm run test:e2e` запускает Playwright в Chromium для настольного и мобильного размера экрана, а также проверки HTTP-адаптера с подменёнными ответами API.
- Серверные интеграционные тесты используют отдельную тестовую базу PostgreSQL. Команда `cd backend && ./mvnw verify` требует настроенных `TEST_DB_URL`, `TEST_DB_USERNAME` и `TEST_DB_PASSWORD`; тесты очищают таблицы своей базы.
- В проекте нет платежей, загрузки файлов, восстановления пароля и реальной интеграции с языковой моделью.

Каталог [demo/](demo/) содержит отдельный пример на JavaFX. Он не используется в основном веб-приложении и запускается независимо.
