Needboard — Java-бэкенд MVP

Пользователь размещает потребность, другие предлагают решения, владелец выбирает одно. Реализована серверная часть участника 2: пользователи, черновики, публикация, предложения и выбор решения. Фронтенд и ИИ-диалоги подключаются отдельными участниками; ручное заполнение карточки уже позволяет проверить основной сценарий.

**Стек проекта:** Java 21 (целевой уровень компиляции), Spring Boot 4.1.1, Spring MVC, Spring Security, Spring Data JPA, PostgreSQL и Flyway. Maven 3.9.16 запускается через Wrapper. Локальная проверка выполнена на JDK 26 и PostgreSQL 18. Spring AI 2.0.x совместим с этой веткой Boot; подключение провайдера и ключей относится к работе участника 3.

Совместимость: [Spring Boot](https://docs.spring.io/spring-boot/system-requirements.html), [Spring AI](https://docs.spring.io/spring-ai/reference/getting-started.html).

**Запуск на Windows с установленным PostgreSQL не требует Docker.** В PowerShell из корня проекта:

~~~powershell
.\scripts\Start-Dev.ps1
~~~

Скрипт использует бинарники PostgreSQL из C:\Program Files\PostgreSQL\18\bin. Создаёт отдельный кластер в .local/postgres, случайный локальный пароль, базу needboard на порту 5433, собирает JAR и запускает сервер на 8080. Существующие службы и базы PostgreSQL не изменяются. Данные сохраняются между запусками; Ctrl+C завершает приложение, после чего скрипт останавливает свой кластер. Другой путь или порты:

~~~powershell
.\scripts\Start-Dev.ps1 -PostgresBin 'D:\PostgreSQL\18\bin' -DatabasePort 55433 -HttpPort 8081
~~~

Если политика PowerShell запрещает запуск локального скрипта, можно выполнить разовый запуск, не меняя системную политику:

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Dev.ps1
~~~

Проверка доступности: GET http://localhost:8080/actuator/health возвращает status UP. Готового веб-интерфейса на главной странице пока нет; это API-сервер.

**Альтернативный запуск — с Docker Compose.**

1. Скопировать .env.example в .env и задать DB_PASSWORD.
2. Запустить базу:

~~~powershell
docker compose up -d db
$env:DB_PASSWORD = 'тот же пароль, что в .env'
.\mvnw.cmd spring-boot:run
~~~

.env автоматически читает Docker Compose. Для Java-процесса пароль нужно передать переменной окружения или настройкой запуска IDE. Кластер из Start-Dev и Compose используют один порт 5433, запускать их нужно по очереди.

При использовании уже существующего сервера создать отдельную базу и пользователя, затем передать DB_URL, DB_USERNAME и DB_PASSWORD. Схему создаёт Flyway при старте; Hibernate только проверяет её. Для HTTPS-развёртывания установить COOKIE_SECURE=true.

**Переменные окружения описывают подключение и запуск.**

| Переменная | Значение по умолчанию |
|---|---|
| DB_URL | jdbc:postgresql://localhost:5433/needboard |
| DB_USERNAME | needboard |
| DB_PASSWORD | Обязательная; значения в репозитории нет |
| PORT | 8080 |
| COOKIE_SECURE | false для локального HTTP |

**Проверки выполняются на настоящем PostgreSQL.** На Windows:

~~~powershell
.\scripts\Test-Backend.ps1
~~~

Скрипт создаёт новый временный кластер на 127.0.0.1:55432, выполняет clean verify и останавливает кластер. Кластер приложения и существующие базы не используются. Проверяются авторизация, смена сессии и CSRF-токена, приватность черновиков, валидация, права на публикацию и принятие, дубли предложений и одновременный выбор двух решений.

На других системах подготовить отдельную пустую тестовую базу, указать TEST_DB_URL, TEST_DB_USERNAME, TEST_DB_PASSWORD и выполнить ./mvnw verify. Тесты очищают таблицы этой базы перед каждым сценарием; она должна быть отдельной от рабочих данных.

Для проверки через реальные HTTP-запросы сначала запустить приложение, а во втором терминале:

~~~powershell
.\scripts\Demo-Api.ps1
~~~

Создаются три демонстрационных аккаунта с уникальными адресами, карточка и два предложения. Скрипт выбирает одно и проверяет сохранённый результат. Он печатает идентификаторы; пароли и сессионные токены не выводятся. Скрипт можно запускать повторно.

**Контракты и границы работы команды:**

- [API и примеры JSON](docs/api/README.md) — для фронтендера и разработчика ИИ.
- [Рейтинг готовности: подтверждения, версии и каталог](docs/api/READINESS.md).
- [Общий план задач](TEAM_TASKS.md).
- kz.needboard.identity — авторизация и CurrentUser для получения пользователя на сервере.
- kz.needboard.needs — карточки; needs.api.NeedCardDraft и NeedCardRules доступны ИИ-модулю.
- kz.needboard.proposals — решения и выбор.
- kz.needboard.common — единый формат ошибок и списков.
- src/main/resources/static — место для фронтенда; REST API доступен с того же адреса.
- Будущий kz.needboard.clarification — модуль участника 3; API уточнения ещё не реализовано.

Одно обращение к ИИ готовит proposed/suggestedCard. Фронтенд показывает её пользователю и передаёт утверждённые поля обычному API карточек. ИИ не публикует карточку.

Исходный C#-проект: [Project_university](https://github.com/Anuar366/Project_university). Сценарии Vacancy/Application адаптированы в Need/Proposal, бизнес-логика вынесена из контроллеров в сервисы. Старые аккаунты и данные автоматически не импортируются.

.local, .cache, .env и target исключены из Git. Локальные данные, пароли и кэш Maven не нужно передавать другим участникам.
