# Рейтинг готовности задачи

Требования пользователя от 23 сентября 2026 года. Источник: присланный скриншот и пояснение в чате. Расчёт реализован в Java API и отдельно в деморежиме фронтенда. [Контракт интеграции](api/READINESS.md).

## Назначение и правила

Рейтинг отражает готовность конкретной бизнес-задачи к работе со студентами, а не известность компании. Он показывает, насколько реально начать работу без дополнительных уточнений.

- Баллы начисляются только за заполненные и подтверждённые поля. Предложения ИИ без подтверждения пользователя не дают баллов.
- Низкий рейтинг не скрывает опубликованную задачу из каталога и не запрещает отклик.
- После каждого подтверждённого дополнения рейтинг пересчитывается.
- Максимальная сумма — 100 баллов. В скриншоте не заданы частичные баллы внутри показателя; для MVP предполагается полный вес за выполненный показатель либо 0.
- Уровень готовности отделён от жизненного цикла объявления: черновик, публикация и выбор решения. Низкая готовность не должна автоматически переводить опубликованную задачу в приватный черновик.

## Показатели

| Показатель | Вес | Условие начисления |
|---|---:|---|
| Контекст и потребность | 20 | Понятно, что происходит сейчас и что необходимо изменить. |
| Данные и материалы | 20 | Указаны доступные данные, примеры или источники. |
| Ожидаемый результат | 15 | Описан конкретный результат работы команды. |
| Критерии успеха | 15 | Есть измеримые признаки принятия решения. |
| Ограничения | 10 | Указаны сроки, технологии, доступы или иные границы. |
| Пользователи | 10 | Понятно, для кого создаётся решение. |
| Связь с бизнесом | 10 | Есть контакт, формат консультаций и порядок обратной связи. |

Наличие непустой строки само по себе не доказывает выполнение содержательного условия. Нельзя начислять баллы за неподтверждённые догадки ИИ или автоматически считать любое заполнение достаточным.

## Уровни готовности из скриншота

| Баллы | Уровень | Поведение |
|---|---|---|
| 0–39 | Черновик / требует уточнения | Опубликованная задача видна в каталоге и помечена как требующая уточнения; отклик разрешён. Это название уровня готовности, а не статус DRAFT. |
| 40–69 | Рабочая | Отклик разрешён; система может рекомендовать задачу. |
| 70–89 | Готовая | Задача получает повышенную позицию в каталоге. |
| 90–100 | Приоритетная | Задача полностью готова к работе и выделяется в каталоге. |

## Ориентиры для реализации

- Рассчитывать итог и разбивку по семи показателям на сервере; клиент не присылает доверенное итоговое число.
- Явно учитывать подтверждение пользователем, привязанное к текущему содержимому полей. Продумать пересчёт при изменении или удалении ранее подтверждённых сведений, чтобы старые баллы не сохранялись за отсутствующий текст.
- Возвращать в API сумму, уровень и понятную разбивку: что засчитано и чего не хватает.
- Проверить доступность отклика на опубликованные задачи с низким баллом. Не добавлять минимальный балл для публикации или отклика.
- Показать баллы и уровень в карточке и каталоге; для низкого балла показать подсказки, а не запрет действий.
- Уточнить механизм повышения позиции и выделения в существующем каталоге при реализации; не придумывать дополнительные условия допуска.
- Проверить границы 39/40, 69/70, 89/90; отсутствие баллов без подтверждения; пересчёт после подтверждения; сохранение видимости и возможности отклика при низком рейтинге.

## Контекст репозитория для продолжения в CLI

- Рабочая папка команды: `C:\Users\Anyar\hack-aa1c5b09-team`. Реализацию делать здесь.
- `backend/` — Java / Spring Boot / PostgreSQL. API карточек: `/api/needs`; предложений: `/api/needs/{id}/proposals`. Контракт: `backend/docs/api/README.md`.
- `frontend/` — React / TypeScript / Vite. По умолчанию работает в mock-режиме. HTTP-адаптер подключён к Java API; в режиме `VITE_API_MODE=http` рейтинг и подтверждения приходят с сервера.
- `demo/` — старый JavaFX-пример, не веб-приложение MVP.
- Бэкенд и фронтенд ранее запущены и проверены отдельно. Реального ИИ-модуля уточнений пока нет; его разрабатывает третий участник.
- Подтверждения, разбивка баллов, пересчёт после изменений и сортировка общего каталога реализованы на сервере. Интерфейс показывает рейтинг, позволяет подтверждать сведения и дополнять опубликованную задачу. Каталог сортируется по готовности и выделяет приоритетные карточки.
