# Рейтинг готовности: контракт для фронтенда и ИИ

Требования и веса: [READINESS_RATING.md](../READINESS_RATING.md). Рейтинг считается сервером; фронтенд показывает ответ `Need.readiness`. Рейтинг не влияет на право публикации или отклика.

## Поля ответа Need

- `revision`: номер версии карточки и подтверждений. Получать актуальное значение из каждого ответа.
- `readiness.score`: 0–100.
- `readiness.maxScore`: 100.
- `readiness.level`: `NEEDS_CLARIFICATION` (0–39), `WORKABLE` (40–69), `READY` (70–89), `PRIORITY` (90–100).
- `readiness.catalogPriority`: 0 до 70 баллов, 1 для 70–89, 2 для 90–100.
- `readiness.criteria`: семь элементов `{criterion, label, description, weight, filled, confirmed, points}`. `filled` проверяет наличие сведений; это ещё не подтверждение их содержания. `points` равен полному весу только при `filled && confirmed`.

В MVP владелец явно подтверждает соответствие текста условию из `description`. Автоматической проверки смыслового качества моделью нет. Неподтверждённый текст ИИ не даёт баллов. Существующие карточки после миграции V4 получают 0 баллов и пустой набор подтверждений.

## Подтверждение

`PUT /api/needs/{id}/readiness-confirmations`, сессия владельца и CSRF:

```json
{
  "revision": 3,
  "confirmedCriteria": ["CONTEXT", "RESULT"]
}
```

Запрос целиком заменяет набор подтверждений. Пустой массив снимает все подтверждения. Повторить тот же набор с актуальной версией допустимо. Ответ — полный обновлённый Need; читать новую `revision` из ответа, не вычислять её на клиенте.

| criterion | Вес | Поля Need.card |
|---|---:|---|
| CONTEXT | 20 | problem |
| MATERIALS | 20 | materials |
| RESULT | 15 | expectedResult |
| SUCCESS | 15 | acceptanceCriteria: минимум один измеримый признак |
| CONSTRAINTS | 10 | constraints, requirements, deadline или deadlineText |
| USERS | 10 | targetUsers |
| BUSINESS | 10 | businessContact, consultationFormat и feedbackProcedure одновременно |

400 VALIDATION_ERROR: не хватает полей показателя; изменения не применяются частично. Неизвестный критерий и попытка передать итоговый балл тоже отклоняются. 403 — чужая карточка/неверный CSRF. 409 STALE_NEED — содержимое изменилось после проверки пользователем. Получить карточку заново и предложить проверить новые сведения; автоматически повторять подтверждение с новой версией нельзя.

## Изменения и каталог

1. Владелец сохраняет поля через `PUT /api/needs/{id}` с `revision`, `originalDescription` и полным `card`.
2. Сервер снимает подтверждения только тех показателей, чьи значения изменились (или были удалены). Например, изменение материалов снимает 20 баллов; изменение заголовка не сбрасывает подтверждение контекста.
3. Владелец повторно проверяет изменившиеся сведения и подтверждает их отдельным запросом.

Дополнять можно DRAFT и PUBLISHED; после SOLUTION_SELECTED изменение и подтверждение закрыты. Обновление опубликованной карточки сохраняет публикацию и существующие отклики. Снижение баллов не скрывает задачу.

`GET /api/needs`: сначала приоритетные (90+), затем готовые (70+), затем остальные. В каждой группе — новые первыми, при равной дате используется id. Сортировка выполняется в PostgreSQL до пагинации. `GET /api/me/needs` сохраняет прежнюю сортировку по дате; это личный список, а не общий каталог.

## Сопоставление с текущим фронтендом

HTTP-адаптер фронтенда использует Java API `/api/needs`, сессию и CSRF. Для подключения установите `VITE_API_MODE=http`; Vite перенаправляет `/api` на бэкенд. По умолчанию доступен автономный mock-режим. Ответы уточняющего диалога сначала хранятся в браузере: сохраните карточку перед подтверждением критериев.

| Frontend NeedCard | Backend NeedCardDraft |
|---|---|
| description | problem |
| outcome | expectedResult |
| successCriteria (строки через перенос) | acceptanceCriteria (массив, до 30 строк по 500 символов) |
| requirements | constraints |
| materials, targetUsers, businessContact, consultationFormat, feedbackProcedure | Одноимённые поля |

Свободный текст бюджета и сроков сохраняется в `budgetText` и `deadlineText`; формат — в `workFormat`. `readiness` и `revision` передаются в UI без пересчёта клиентом. Формула в `frontend/src/api/readiness.ts` предназначена только для демонстрационных данных.
