# Ясно — от потребности к решению

MVP команды «А да нууууу». React-фронтенд подключён к Java/Spring backend через единый HTTP-адаптер.

Потребитель описывает идею → уточняет задачу с ИИ → публикует карточку. Исполнитель находит её в каталоге → отправляет решение → обсуждает его с заказчиком. Заказчик выбирает исполнителя; в «Моих предложениях» обновляется статус.

## Полный запуск с backend

Нужны Docker Desktop, Java 21+ и Node.js 22.12+. Сначала запустите Docker Desktop, затем из корня проекта:

```sh
./scripts/start-dev.sh
```

Откройте http://127.0.0.1:5173. Скрипт запускает PostgreSQL на `5433`, backend на `8080` и frontend на `5173`. Остановка — `Ctrl+C`; контейнер базы сохраняет данные между запусками.

Если файл `backend/.env` отсутствует, для локальной базы используется пароль `needboard-local-dev`. Свой пароль можно задать в `backend/.env` по примеру `backend/.env.example`.

## Только frontend-демо

Нужен Node.js 22.12+ (проверено на Node.js 24).

```sh
cd frontend
npm ci
npm run dev
```

Открыть http://127.0.0.1:5173 и нажать **«Открыть демо»**. Этот режим не требует Docker и Java.

По умолчанию используется `mock` без сервера. Данные сохраняются в браузере. ИИ и подготовленные демоисполнители отвечают по сценарию; между локальными аккаунтами можно отправлять свои предложения и сообщения. Кнопка «Демо исполнителя» открывает вторую сторону сценария. На опубликованную заявку также добавляются три демонстрационных предложения.

В серверном режиме регистрация автоматически выполняет вход, карточки и предложения хранятся в PostgreSQL, а сообщения передаются через backend. Уточняющий диалог пока использует локальный сценарий вопросов в браузере; итоговая карточка сохраняется на сервере.
