# Фронтенд Ясно

React + TypeScript + Vite, React Router, TanStack Query, CSS Modules, Lucide. Шрифт Manrope поставляется локально через Fontsource; внешние сервисы для работы демо не нужны.

## Запуск и проверка

```sh
npm ci
npm run dev
```

Dev-сервер: http://127.0.0.1:5173. Node.js 22.12+ или 24.

```sh
npm run build
npm run preview
npx playwright install chromium
npm run test:e2e
```

`build` включает проверку типов. Playwright сам запускает два сервера: mock на 4173 и HTTP на 4174. Порты должны быть свободны. Тесты проверяют пользовательский сценарий на desktop и мобильном viewport Chromium, а также HTTP-адаптер с перехваченными ответами сервера. Это не тест реального бэкенда или мобильного Safari.

## Режимы

Скопировать `.env.example` в `.env.local` и перезапустить Vite:

```dotenv
VITE_API_MODE=mock
VITE_API_BASE_URL=/api
```

- `mock` — все операции локальны. «Открыть демо» открывает Александра с тремя примерами заявок; «Демо исполнителя» — Алису. Любой аккаунт может публиковать потребности и отправлять предложения другим пользователям. Новый аккаунт начинает с пустых личных списков.
- `http` — реальные запросы к Spring backend с cookie-сессией и CSRF. Vite проксирует `/api` на `http://127.0.0.1:8080`, поэтому отдельная настройка CORS не нужна. Кнопка демо и демонстрационные подписи скрыты.

Все `VITE_*` значения публичны. Секреты ИИ и ключи провайдеров должны находиться на сервере.

## Что можно показать

1. Войти в демо или зарегистрироваться с вымышленными данными.
2. Создать заявку: например, «Нужен фирменный стиль для новой кофейни».
3. Ответить на семь уточнений. Любой вопрос можно пропустить; неизвестные поля не заполняются выдуманными значениями.
4. Проверить и изменить карточку. Для публикации нужны название, описание и результат.
5. Опубликовать; в mock появятся три предложения. Обсудить условия с двумя исполнителями.
6. Подтвердить выбор одного. Выбранный чат остаётся активным; остальные доступны для чтения.
7. Перезагрузить страницу: карточка, выбор и переписка сохраняются.

## Сценарий двух пользователей

1. Открыть «Демо исполнителя», перейти в «Каталог» и выбрать потребность Александра — например, фирменный стиль кофейни.
2. Заполнить описание решения, способ реализации, стоимость и сроки. Отправить предложение и написать заказчику в чате.
3. В «Моих предложениях» проверить статус «Ожидает решения».
4. Выйти и нажать «Открыть демо». В «Моих потребностях» открыть эту заявку, найти отклик Алисы, ответить в чате и принять предложение.
5. Снова войти через «Демо исполнителя»: статус изменится на «Принято», а ответ заказчика будет в переписке.

Можно также зарегистрировать два своих аккаунта и повторить путь с новой потребностью. В mock переключайте аккаунты последовательно в одном профиле браузера: данные общие через localStorage, активная сессия одна. Разные устройства и профили не обмениваются мок-данными; для этого нужен сервер.

Каталог показывает открытые чужие потребности, поддерживает поиск и фильтр категории. Свои заявки и черновики в него не попадают. Закрытые потребности остаются доступны по ссылке из своих предложений, но больше не принимают отклики. Для одной потребности можно отправить только одно предложение от аккаунта; редактирование и отзыв предложения вне MVP.

## Данные и ограничения

- Mock-авторизация — имитация, **не защита данных**. Пароли не сохраняются и не проверяются на совпадение: для входа нужен email существующего локального аккаунта и любая строка от 8 символов. Используйте вымышленные данные. Реальный вход обеспечивает сервер в `http`-режиме.
- `localStorage`: `yasno-demo-v1` (демоданные), `yasno-demo-session` (идентификатор демонстрационного пользователя). Для сброса демо удалить эти два ключа и обновить страницу.
- `sessionStorage`: несохранённый ввод новой заявки, ответа ИИ, правок, формы предложения и сообщений. Ключи содержат идентификатор пользователя и заявки/предложения. Неотправленные тексты переживают перезагрузку в той же вкладке; отправленные данные сохраняются через API.
- При ошибке отправки текст остаётся в поле. Повтор использует тот же `clientId`, пока текст не изменён. Сервер обеспечивает идемпотентность. Автоматических повторов мутаций нет.
- Чат, «Мои предложения» и открытая карточка каталога опрашиваются раз в 5 секунд; каталог и полученные предложения — раз в 15 секунд. В скрытой вкладке опрос останавливается; при возвращении данные обновляются.
- Подготовленные демоотклики отвечают автоматически. Предложения, отправленные пользователями, получают только настоящие сообщения этих локальных аккаунтов. Новым участникам не приписываются отзывы или рейтинг.
- Обновление добавляет примеры каталога и демоаккаунты к существующему хранилищу без сброса черновиков, предложений и переписок.
- Опубликованную заявку нельзя редактировать; выбор исполнителя окончательный. Платежи, файлы, отмена выбора и восстановление пароля не входят в MVP.
- На хостинге нужен SPA fallback: все маршруты интерфейса должны отдавать `index.html`. Настройки `VITE_*` встраиваются при сборке.

## Структура

- `src/pages/` — вход, свои потребности, каталог, создание/уточнение, свои/полученные предложения и сообщения.
- `src/components/` — каркас, карточка, чат и общие элементы.
- `src/api/types.ts` — общий контракт; `mock.ts` и `http.ts` — взаимозаменяемые реализации.
- `src/styles/` — оформление и адаптивная вёрстка.
- `tests/` — сквозные сценарии и проверки отказов API.

## Подключение команды

Согласовать [API.md](API.md). Сервер отвечает за доступ только к своим заявкам, безопасную сессию, валидацию, ограничения статусов и атомарность выбора. Затем переключить `VITE_API_MODE=http`, задать URL и проверить реальную регистрацию, генерацию и доставку сообщений.
